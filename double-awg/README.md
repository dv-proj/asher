# DoubleAWG на AmneziaWG

[RUS](README.md) [ENG](README-EN.md)

`deploy-doubleawg.sh` разворачивает каскадный VPN (DoubleAWG) из двух VPS на Ubuntu 24.04 с [AmneziaWG](https://docs.amnezia.org/documentation/amnezia-wg/) в режиме модуля ядра. Скрипт запускается на вашей машине (Linux или WSL) и настраивает оба сервера по SSH.

```
Клиенты ──IPv4──▶ VPS1 [gate1 … gateN │ inway] ══IPv6══▶ VPS2 [outway] ──IPv4/NAT──▶ Интернет
                        │
                        └── split: российские IP — напрямую с VPS1
```

- **Канал** — туннель `inway` (VPS1) ↔ `outway` (VPS2). Адреса внутри Канала — IPv6 ULA, транспорт между серверами — IPv6. Если IPv6 нет, скрипт предложит IPv4. Выход в интернет с VPS2 — IPv4 через NAT.
- **Входные интерфейсы** (`gate1`, `gate2`, …) — точки подключения клиентов на VPS1. У каждого своя версия AmneziaWG, порт, подсеть, MTU, режим подключения и настройка split.
- **Kill-switch.** Трафик клиентов уходит только в Канал. Если Канал не работает, трафик блокируется, а не идёт в интернет с IP входного сервера.
- **Split** (для каждого входного интерфейса отдельно). Трафик к российским IPv4 идёт напрямую с VPS1, остальной — через Канал.

## Возможности

- Установка актуальной AmneziaWG из официального PPA `ppa:amnezia/ppa` (модуль ядра через DKMS). Если для загрузки модуля нужна перезагрузка, скрипт перезагрузит VPS (с подтверждением) и продолжит.
- Версии протокола **1, 1.5, 2, 3, 3.1**, отдельно для Канала и для каждого входного интерфейса.
- Ключи первой установки генерируются локально через `wg` и сохраняются в файл результата с пометками.
- Сетевые интерфейсы и адреса узлов определяются автоматически, с подтверждением пользователя.
- Два режима входного интерфейса:
  - `listen` — клиенты подключаются к серверу (телефоны, ноутбуки);
  - `connect` — сервер сам подключается к клиенту. Подходит для роутера с белым IP: у клиента в конфиге `ListenPort`, у сервера — `Endpoint` клиента.
- Подсеть каждого входного интерфейса задаётся независимо (`/8`…`/30`), подсети не обязаны быть смежными. VPS2 подсетей клиентов не знает, поэтому новые входы добавляются без изменений на VPS2.
- Скрипты управления на серверах: добавить или удалить входной интерфейс, добавить или удалить клиента, удалить Канал.
- Правила ufw (если он установлен) с пометкой `DoubleAWG`.

## Требования

**Машина запуска:** Linux или WSL, bash 4.4+, `ssh` с доступом к обоим VPS по ключу, `wireguard-tools` (команда `wg`), `tar`.

**VPS:**
- Ubuntu 24.04 на KVM или выделенном сервере. На OpenVZ и LXC загрузить модуль ядра нельзя.
- Пользователь `root` или пользователь с `sudo`. Если sudo требует пароль, его спросят во время установки.
- Для транспорта по IPv6 у VPS2 нужен публичный IPv6, у VPS1 — маршрут IPv6 по умолчанию.
- Ядро из репозитория Ubuntu. Если для работающего ядра нет `linux-headers`, скрипт поставит актуальное ядро и предложит перезагрузку.
- Secure Boot должен быть выключен, иначе ядро не загрузит неподписанный модуль DKMS.

## Быстрый старт

```bash
curl -fsSL https://raw.githubusercontent.com/dv-proj/asher/main/double-awg/deploy-doubleawg.sh | bash
```

Скрипту нужен bash, поэтому запускайте через `bash`, а не `sh`. Вопросы он задаёт через терминал, так что запуск через конвейер работает. Если хотите сначала прочитать скрипт, скачайте его и запустите:

```bash
curl -fsSLO https://raw.githubusercontent.com/dv-proj/asher/main/double-awg/deploy-doubleawg.sh
bash deploy-doubleawg.sh
```

Значения по умолчанию можно задать заранее: `ENTRY_SSH`, `EXIT_SSH`, `ENTRY_SSH_PORT`, `EXIT_SSH_PORT`, `OUT_DIR`.

```bash
ENTRY_SSH=root@203.0.113.10 EXIT_SSH=root@198.51.100.20 \
  bash -c "$(curl -fsSL https://raw.githubusercontent.com/dv-proj/asher/main/double-awg/deploy-doubleawg.sh)"
```

### Что спрашивает скрипт

| Шаг | Вопрос | По умолчанию |
|---|---|---|
| SSH | `user@host` и порт для VPS1 (вход) и VPS2 (выход) | — / `22` |
| Узлы | подтверждение найденных интерфейсов, публичных IPv4 и IPv6 | автоопределение |
| Имена | выход из Канала (VPS2), вход в Канал (VPS1), префикс входных интерфейсов | `outway`, `inway`, `gate` |
| Канал | версия AmneziaWG, UDP-порт `outway`, DNS для клиентов, I1 (имитация QUIC) | `2`, случайный, `1.1.1.1, 1.0.0.1`, да |
| Вход N | версия AWG, подсеть, режим, UDP-порт, split, имя первого клиента, для `connect` — `host:port` клиента | версия Канала, `10.8.N.0/24`, `listen`, случайный, да, `client1` |
| | «Добавить ещё один входной интерфейс?» | нет |

Перед установкой скрипт показывает сводку и просит подтверждения. Сначала настраивается VPS2, потом VPS1. В конце скрипт проверяет, что Канал поднялся: есть рукопожатие и проходит ping6 по адресам внутри Канала.

## Версии AmneziaWG

| Версия | Параметры в конфиге |
|---|---|
| 1 | `Jc`, `Jmin`, `Jmax`, `S1`, `S2`, `H1`–`H4` (одиночные значения) |
| 1.5 | версия 1 + `I1` |
| 2 | + `S3`, `S4`, `H1`–`H4` диапазонами |
| 3 | + `HeaderProtectionKey`, `ContentPaddingAddition`; `S1`–`S4` ≥ 12, `H1`–`H4` = 1…4 |
| 3.1 | версия 3 + `RandomTrailers`, `DisableCookies` |

Как подбираются параметры:
- значения генерируются случайно с учётом ограничений протокола: размеры пакетов рукопожатия не совпадают, диапазоны `H` не пересекаются, `Jmax` ≤ 1280;
- `I1` — пакет перед рукопожатием, похожий на начальный пакет QUIC (1200 байт);
- тайминги версии 3 (`RekeyAfterTime` и другие) не задаются, остаются значения WireGuard.

Перед запуском каждый конфиг проверяется на временном интерфейсе. Если модуль на сервере не поддерживает параметры выбранной версии, установка останавливается с понятной ошибкой.

Версии 3 и 3.1 понимают только свежие клиенты (AmneziaVPN 5.0.1.5+). Многие роутеры и старые приложения поддерживают версии не выше 2.

## Управление на серверах

Скрипты лежат рядом с конфигами в `/etc/amnezia/amneziawg/`, запускаются через `sudo`.

### VPS1 (вход)

Скриптов нет в `PATH`, поэтому запускайте их по полному пути:

```bash
D=/etc/amnezia/amneziawg

# входной интерфейс: интерактивно или параметрами
sudo $D/dawg-gate-add.sh
sudo $D/dawg-gate-add.sh --awg 2 --mode listen --net 192.168.181.0/24 --port 40005 --split yes --yes
sudo $D/dawg-gate-add.sh --help
sudo $D/dawg-gate-del.sh gate2                        # вместе с клиентами

# клиенты
sudo $D/dawg-client-add.sh gate1 phone                # listen: выводит конфиг и QR (если есть qrencode)
sudo $D/dawg-client-add.sh gate2 router --endpoint home.example.net:51820   # connect
sudo $D/dawg-client-del.sh gate1 phone

# split
sudo $D/dawg-entry.sh split-status
sudo $D/dawg-entry.sh split-up gate1
sudo $D/dawg-entry.sh split-down gate1
sudo $D/dawg-entry.sh split-update                    # обновить список российских подсетей

# удалить Канал, все входные интерфейсы и таймер (с --purge — ещё пакеты AmneziaWG и PPA)
sudo $D/dawg-channel-del.sh [--purge]
```

Параметры `dawg-gate-add.sh`:

| Параметр | Значение |
|---|---|
| `--awg` | `1`, `1.5`, `2`, `3`, `3.1` (по умолчанию — версия Канала) |
| `--mode` | `listen` или `connect` |
| `--net` | подсеть клиентов `A.B.C.D/N`, N от 8 до 30. Адрес сервера — первый в подсети. Подсеть не должна пересекаться с другими входами и маршрутами сервера |
| `--port` | UDP-порт (по умолчанию случайный свободный) |
| `--mtu` | MTU интерфейса и его клиентов (по умолчанию **1280**) |
| `--dns`, `--split yes\|no`, `--i1 yes\|no`, `--num N`, `--yes` | DNS, split, I1, номер интерфейса, работа без вопросов |

Конфиги клиентов сохраняются в `/etc/amnezia/amneziawg/clients/<интерфейс>/<клиент>.conf`. Ключи интерфейсов и клиентов, добавленных позже, генерирует сервер (`awg genkey`).

### VPS2 (выход)

```bash
sudo /etc/amnezia/amneziawg/dawg-channel-del.sh [outway2] [--purge]   # без имени — удалить все outway-интерфейсы
```

## Несколько входных VPS на одном выходном

На одном VPS2 может быть несколько outway-интерфейсов (`outway`, `outway2`, …), по одному на каждый входной VPS. У каждого свои порт, ключи и IPv6-подсеть Канала. Подсети клиентов VPS2 по-прежнему не знает, поэтому у разных входных VPS они могут быть любыми.

Чтобы подключить ещё один входной VPS к существующему выходному, запустите скрипт заново и укажите существующий VPS2. Скрипт найдёт outway-интерфейсы и спросит, что делать:

1. **заменить (перенастроить)** найденный интерфейс. Подключённый к нему входной VPS потеряет Канал, пока его не перенастроят;
2. **добавить** новый интерфейс (по умолчанию). Остальные интерфейсы не затрагиваются.

Для неинтерактивного запуска: `EXIT_ACTION=add|replace` и `EXIT_OUTWAY=<имя интерфейса>`.

## Split-маршрутизация

Split включается и выключается двумя строками в `.conf` входного интерфейса:

```ini
PostUp = /etc/amnezia/amneziawg/dawg-entry.sh split-up gate1
PostDown = /etc/amnezia/amneziawg/dawg-entry.sh split-down gate1
```

Закомментируйте или раскомментируйте обе строки и выполните `sudo systemctl restart awg-quick@gate1`. Без перезапуска — командами `split-up` и `split-down`.

- **Список подсетей.** Российские IPv4-подсети берутся по очереди из статистики RIPE NCC (delegated stats), RIPEstat и ipdeny и объединяются. Список хранится в `dawg-ru.txt` и обновляется таймером `dawg-ru-update.timer` раз в неделю.
- **Свои исключения.** В `dawg-ru-extra.txt` — подсети, которые идут напрямую. В `dawg-ru-exclude.txt` — подсети, которые всегда идут в Канал. После правки выполните `split-update`.
- **Точность.** Список основан на стране регистрации подсети, а не на реальном расположении адресов.
- **DNS.** С DNS `1.1.1.1` запросы идут через Канал, и российские сайты с CDN могут отдавать зарубежные адреса. С российским DNS (например, `77.88.8.8`) они пойдут напрямую, но сами DNS-запросы будут видны в России.

## MTU

| Участок | MTU |
|---|---|
| Входные интерфейсы и клиенты | **1280** по умолчанию (`--mtu`). Надёжно и для мобильных сетей. 1380 даёт примерно на 7% меньше накладных расходов, но снаружи пакет получается 1448 байт, и он может не пройти через некоторые сети |
| Канал (`inway`/`outway`) | считается из MTU внешних интерфейсов, транспорта (IPv6 даёт 80 байт заголовков, IPv4 — 60) и `S4`; обычно 1400 |

Для TCP на обоих VPS включено ограничение MSS. MTU клиента в конфиге должен совпадать с MTU входного интерфейса.

## Как это устроено

**VPS1:**
- У каждого входного интерфейса `gateN` своя таблица маршрутизации `7100+N` (правила `ip rule` 31000/31001). В таблице `default dev inway`, а при недоступном Канале — `blackhole` (kill-switch).
- Split добавляет в эту таблицу `throw`-маршруты для российских подсетей, плюс NAT через внешний интерфейс.
- Правила firewall для интерфейса ставятся в `PostUp` и снимаются в `PostDown` (`dawg-entry.sh`).

**VPS2:**
- Соединения, пришедшие из `outway`, помечаются (`CONNMARK`). NAT делается по метке.
- Ответы и собственные ICMP-пакеты VPS2 (traceroute) по метке возвращаются в Канал через таблицу маршрутизации. У каждого outway-интерфейса номер N: метка `0x444e000N`, таблица `7100+N`, `ip rule` `31000+N` (у первого интерфейса N=0). Состояние интерфейсов хранится в `outway.d/<интерфейс>.env`.

**rp_filter.** У интерфейсов Канала нет IPv4-адреса, поэтому проверка обратного пути (`rp_filter`) на них выключена. Общее значение `all` опускается до 0, а остальные интерфейсы сохраняют прежний уровень проверки. Отбор источников на интерфейсах Канала делает сам AmneziaWG через `AllowedIPs`.

**Firewall.** Правила iptables ставятся из `PostUp`/`PostDown`. Если установлен ufw, добавляются его правила с пометкой `DoubleAWG <интерфейс>`. ufw скрипт не включает и не выключает. **Внешний firewall в панели провайдера** нужно настроить вручную: открыть UDP-порт `outway` на VPS2 и порты входных интерфейсов на VPS1.

## Удаление и переустановка

```bash
sudo /etc/amnezia/amneziawg/dawg-channel-del.sh --purge   # сначала VPS1
sudo /etc/amnezia/amneziawg/dawg-channel-del.sh --purge   # затем VPS2
```

`net.ipv4.ip_forward` остаётся включённым до перезагрузки. Повторный запуск `deploy-doubleawg.sh` на входном VPS удаляет его предыдущую установку (вместе с клиентами, ключи создаются новые). На выходном VPS установка не удаляется: скрипт предлагает заменить найденный outway-интерфейс или добавить новый.

## Диагностика

```bash
sudo awg show                                   # рукопожатия и счётчики
sudo /etc/amnezia/amneziawg/dawg-entry.sh split-status                 # VPS1
ip rule; ip route show table 7101 | grep -v throw
sudo iptables -vnL FORWARD | head -20
sudo tcpdump -ni gate1 -c 20                    # что приходит от клиентов
```

| Симптом | Где искать |
|---|---|
| Рукопожатия нет | порт закрыт в firewall провайдера, разные ключи или параметры обфускации, версия 3.x на клиенте, который её не поддерживает |
| Рукопожатие есть, у сервера `received` почти не растёт | не совпадают `S3`/`S4`/`H3`/`H4` у клиента и сервера. Импортируйте конфиг на клиенте заново целиком |
| Российские сайты открываются, остальные нет | Канал: `awg show inway` / `awg show outway`, `ip route get <IP> from <клиент> iif outway` на VPS2 |
| В режиме `connect` нет связи | клиент должен принимать входящий UDP на свой `ListenPort` (firewall или проброс порта на его стороне) |

## Ответственность

Скрипт настраивает сетевые правила и firewall на серверах. Проверьте его в тестовой среде, прежде чем запускать на рабочих серверах, и соблюдайте законы своей страны.
